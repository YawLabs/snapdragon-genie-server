# Snapdragon NPU (Hexagon HTP) via ONNX Runtime QNN Execution Provider.
#
# IMPORTANT: install into a CLEAN venv -- one that has never held another
# onnxruntime or onnxruntime-qnn. See README "Install".
#
# What this note used to say -- "NO plain `onnxruntime`; onnxruntime-qnn ships
# the same `onnxruntime` module and the two collide" -- is true of the old
# onnxruntime-qnn 1.x line (the 1.24.4 wheel carries a whole `onnxruntime/`
# package) and FALSE of the 2.5.0 pinned below, checked 2026-09-17 by opening
# the wheels: 2.5.0 ships only `onnxruntime_qnn/` and declares
# `Requires-Dist: onnxruntime>=1.24.2`. Plain onnxruntime is its dependency,
# not its rival. The venv to avoid is one with a 1.x onnxruntime-qnn left in
# it; the clean fix for that is still a fresh venv (uninstall + --no-deps
# reinstall is NOT reliable -- with 2.5.0 it removes the only `onnxruntime`
# module there is).
#
# Target: Windows on ARM64 (Snapdragon X Elite / X1E80100), Python 3.11-3.14.
# win_arm64 wheels exist for cp311 / cp312 / cp313 / cp314.

onnxruntime-qnn==2.5.0   # plugin EP; pulls `onnxruntime` in as a dependency
# WHICH onnxruntime is not pinned by that wheel (`>=1.24.2`). Everything in the
# README was proven on 1.29.0, which is what this resolved to then; a fresh
# install on 2026-09-17 resolves 1.30.0 (pip --dry-run), which has NOT been run
# here. If the attach misbehaves in a new venv, rebuild it with the proven pair
# pinned in the SAME resolve, before suspecting anything else:
#   pip install onnxruntime==1.29.0 -r requirements.txt
onnx>=1.16               # model construction for the benchmark
numpy>=1.26
